What was wrong in 1.1.0

The scan covered the manifest, PHP class loading, all nine templates, all three stylesheets, the script, the LESS entry point and the docs. Every finding below is fixed in 1.2.0. Unreadable text was counted by an automatic check that measures the real contrast of every visible text run on 43 pages: 1,799 runs fell below 4.5:1 in 1.1.0, and none do now.

Layout and width

  • "Help about MediaWiki" sat in the Navigation menu. It is now removed in PHP (SkinNightSky::buildSidebar), with a CSS fallback.
  • Tools lived inside the left sidebar. It is now its own right-hand column, sticky on wide screens and under the article below 1100px.
  • Width. The whole page was capped at 1320px, leaving empty margins on wide screens. The cap is gone and the article takes all the space between the columns.
  • Wide content. Tables, code and images only scrolled sideways on phones. On desktop, a 40-column table made the 1.1.0 page about 2,000 to 2,600px wider than the window. Wide content now scrolls inside the article at every width.

Unreadable colours

  • No design tokens. Core, OOUI, Codex and extensions paint themselves with var(--background-color-base, #fff). The skin defined none of those variables, so every such box fell back to white while the skin forced light text: the white-box, grey-text look on Recent changes, forms and buttons. tokens.css now defines all 142 colour tokens, and dev/contrast-tokens.py checks their pairs.
  • Dead LESS file. mediawiki.skin.variables.less shipped but was never registered with SkinLessImportPaths, so MediaWiki ignored it. It is registered now.
  • No night-mode flag. SyntaxHighlight, RCFilters, CodeEditor, Echo, VisualEditor and DiscussionTools only switch to their dark styles under html.skin-theme-clientpref-night. The skin never set it. It does now.
  • Syntax highlighter. Light-theme token colours were drawn on the dark background. The extension's own night palette is on, and code blocks have explicit text and surface colours.
  • Forced light widgets. OOUI windows, menus and search suggestions were pinned to color-scheme: light. They follow the dark surfaces now.
  • Invisible icons. OOUI draws icons as dark SVG backgrounds. They are recoloured for dark surfaces, except a checkbox's tick.
  • Controls. Disabled buttons were 1.2:1, unchecked checkboxes and radios were bright white boxes, and the sign-up headings were hard-coded black on black. All fixed.
  • Special-page tables. Version, Statistics, group rights and similar pages use the wikitable class outside the article body. 1.1.0 only styled it inside articles, so those tables kept core's light background under light text.
  • Imported Wikipedia templates (navbox, ambox, hatnote, sortable tables) hard-code light backgrounds. Dark rules now win over TemplateStyles, and a small script, contrast.js, keeps text legible on any light cell left in a page. Add notheme to opt out.

Content markup

  • Infobox. The skin styled div.infobox. Wikipedia's Infobox person outputs table.infobox with infobox-label and infobox-data cells, so the old rules squeezed the table into a fixed 265px box. Both markups are styled properly now.
  • Word wrapping. Long words and web addresses wrap inside their own cell without shrinking a label column to a letter per line, and Recent changes no longer splits ordinary words mid-letter (core sets word-break: break-all there).
  • Headings. Level-1 headings inside articles were underlined twice. Now once.
  • Main Page. The automatic table of contents landed inside the first card, and .card a turned every link in a card into a call-to-action. The contents box is hidden there and only a card's closing link gets the arrow.
  • Article links. Underlines now apply to real links, not red links or images, and red links keep their colour once visited.

Templates, PHP and manifest

  • Extension content dropped. None of the six portlet templates printed html-before-portal, where extensions insert their own markup.
  • Footer. The template skipped the footer's "info" list, where extensions add their own lines, and dropped every list's class name (including noprint on the badges). It now renders info, places and icons.
  • Search. The only submit button was named fulltext, so pressing Enter always searched the text and never jumped to an exact title. A hidden go button now comes first.
  • Landmarks. role="banner" inside an <aside> and role="navigation" around nested <nav> elements gave screen readers extra, nested regions. Fixed.
  • Manifest. The plain SkinMustache class became a small subclass with autoloading, the obsolete targets key is gone, and the core style features the CSS relies on are enabled (accessibility, interface-core, interface-indicators, interface-edit-section-links, interface-user-message, i18n-*).

CSS hygiene

  • Repeated rules. The page shell, content box, footer and background layers were each defined two or three times with different values, so the last copy silently overrode the first. They are merged.
  • Element selectors. footer restyled any <footer> a page or extension contained. It is now #footer.

Packaging and docs

  • Duplicate folder. The 1.1.0 zip carried a second, older copy of the skin in NightSky/NightSky/. 1.2.0 ships one folder.
  • README pointed to a preview file that is not in the package. Removed.
  • Test coverage. 1.1.0 was validated against a wiki with no extensions installed, so the styling of SyntaxHighlight, TemplateStyles and the Recent changes filters was never exercised. 1.2.0 is tested with those extensions, and the new VALIDATION file lists only checks that were run.
